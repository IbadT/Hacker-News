# 📁 Архитектура папок в Next.js

Этот проект использует **feature-based архитектуру**, которая помогает организовать код по логическим модулям.

## 🚀 **Структура проекта**
📦 src/ ┣ 📂 features/ ┣ 📂 shared/ ┣ 📂 views/ ┣ 📂 widgets/ ┗ 📂 pages/

## 📌 **Описание папок**
### **1️⃣ `features/` — Бизнес-логика отдельных модулей**
Здесь хранятся независимые **функциональные модули**, которые содержат API-запросы, store, обработчики данных.

Пример:
📦 features/ ┣ 📂 auth/ → Логика аутентификации ┣ 📂 profile/ → Управление профилем ┗ 📂 cart/ → Корзина покупок

### **2️⃣ `shared/` — Переиспользуемые UI-компоненты**
Содержит глобальные **компоненты, хуки, утилиты и константы**, которые можно использовать в любом модуле.

Пример:
📦 shared/ ┣ 📂 ui/ → UI-элементы (Button, Input) ┣ 📂 hooks/ → Общие хуки (useFetch, useAuth) ┣ 📂 utils/ → Хелперы и функции ┗ 📂 constants/ → Константы и настройки

### **3️⃣ `views/` — Готовые страницы с логикой**
Сюда собираются **страницы**, которые объединяют несколько `features` и `shared`.

Пример:
📦 views/ ┣ 📂 dashboard/ ┣ 📂 settings/ ┗ 📂 orders/

### **4️⃣ `widgets/` — Крупные UI-блоки**
Содержит **комплексные компоненты**, состоящие из `features` и `shared`.

Пример:
📦 widgets/ ┣ 📂 navbar/ ┣ 📂 sidebar/ ┗ 📂 product-card/

## ✅ **Почему использовать такую архитектуру?**
✔ **Чёткое разделение логики и UI**  
✔ **Легко поддерживать и расширять**  
✔ **Удобная переиспользуемость компонентов**

## 🎯 **Рекомендации**
- Всегда **разделяй бизнес-логику** и представление (UI).
- `shared` не должен зависеть от `features`, чтобы избежать циклических зависимостей.
- `views` формируют конечные страницы, а `widgets` — крупные UI-компоненты.
